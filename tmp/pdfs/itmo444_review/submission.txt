          The Bash ensure_target_group function checks whether a target group exists, but it does not
          fully detect or correct configuration drift when an existing target group is changed manually.
          Terraform compares the real AWS resource with the declared configuration and proposes a plan
          to restore the expected settings.

          Question 4:                                                               
          Lambda would be a good fit because both tiers perform short, stateless request-response work
          and already keep persistent data outside the application instances. It would remove the need to
          manage EC2 instances, launch templates, and Auto Scaling groups, although API Gateway,
          cold starts, execution limits, and external API latency would become new considerations.
                                                                                    
          Short answers: how Terraform is like AWS Lambda and where the comparison stops,
                                                                                    
          what Terraform did not make easier, and your answers to the Section 13.1 review
          questions.                                                                
                                                                                    
          Terraform is like AWS Lambda because both are declarative in the sense that I specify the
          desired result and let the service handle much of the underlying execution. The comparison
          stops because Lambda runs application code in response to events, while Terraform provisions
          and manages infrastructure by comparing configuration, state, and real resources.
